# D/V-REPORTCONTRACT6：业务需求到报告输出的契约化操作流

## 目标

把用户操作流做顺：从业务需求确认后的报告框架，进入数据分析和报告输出时能持续看到同一份契约。

## 前置依赖

- D/V-REPORTCONTRACT3（已完成）：报告输出页展示契约来源
- E-REPORTCONTRACT4/5（并行）：本卡只预留接口桩，不阻断

## 实施范围（4 个子任务）

### T1: BusinessRequirementPane — 新增"带入工作视图"入口

**文件**: `web/src/components/BusinessRequirementPane.tsx` + `web/src/tabs/EngineTabs.tsx`

**改动**:
1. BusinessRequirementPane Props 新增 `onBringToChat?: () => void`
2. 在分析框架 tab 底部操作区（与现有"在数据探索中验证"按钮并列），新增"带入工作视图"按钮
3. 条件：`onBringToChat` 存在 + `activeConfirmedRequirement` 存在 + 非 stale
4. 点击时：将当前确认需求上下文存入模块级 store → 调用 `onBringToChat()`
5. EngineTabs wiring：`onBringToChat={() => ctx.setActiveSubTab("view")}`

**模块级 store**: 新建 `web/src/lib/activeContractContext.ts`（~15 行）
```ts
// 跨子 tab 持久化的"当前活跃契约上下文"（模块级单例，不碰 App.tsx）
type ActiveContractCtx = { pathId: number; markdownPath: string; jsonPath?: string } | null;
let _active: ActiveContractCtx = null;
export function setActiveContractContext(ctx: ActiveContractCtx) { _active = ctx; }
export function getActiveContractContext(): ActiveContractCtx { return _active; }
```

### T2: ChatPane — 合约摘要展示 + 预选版本

**文件**: `web/src/components/ChatPane.tsx`

**改动**:
1. 在聊天工具栏（业务需求下拉框旁边）新增契约摘要区域：
   - 选中业务需求版本后，调用 `api.getReportContractContext` 获取契约
   - 显示紧凑摘要：项目名 + 场景 + 章节数 + 必答问题数 + fallback 标记
   - fallback 时显示琥珀色提示
   - 未选中时隐藏（不阻断普通聊天）
2. 预选逻辑：组件 mount 时检查 `getActiveContractContext()`，如果返回非 null 且在已加载版本列表中存在匹配，则自动选中
3. 清除/切换：用户可通过现有下拉框切换版本，契约摘要随选择更新

**安全约束**:
- 契约摘要只展示元数据（projectName/scene/sectionCount），不读 draw_data
- 不修改 `onSend` 签名或消息发送逻辑

### T3: ReportContractPane — 自动化覆盖检查

**文件**: `web/src/lib/api.ts` + `web/src/components/ReportContractPane.tsx`

**改动**:

**api.ts 新增 2 个方法**:
```ts
contractReview: (pathId: number, relPath: string, contractContext?: unknown) =>
  fetch("/api/report-review/contract-review", {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ pathId, relPath, reportContractContext: contractContext }),
  }).then(json<ContractReviewResult>),

contractAutoFix: (pathId: number, relPath: string, model?: string, contractReview?: unknown) =>
  fetch("/api/report-review/contract-auto-fix", {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ pathId, relPath, model, contractReview }),
  }).then(json<ContractAutoFixResult>),
```

**ReportContractPane 改动**:
1. 选中报告文件后（从 FolderPathsPane 传入），调用 `contractReview` 获取覆盖结果
2. 替换手动清单为自动化覆盖结果展示：
   - **已覆盖** (status=covered): 绿色 ✓
   - **部分覆盖** (status=partial): 琥珀色 △
   - **缺失** (status=missing): 红色 ✗
3. 展示 evidenceGaps（缺证据）、unsupportedClaims（无依据断言）、openQuestionMisuse（误用待确认问题）
4. "按框架审查"按钮触发覆盖检查
5. E-REPORTCONTRACT5 就绪后展示"一键修订"按钮（当前隐藏，条件渲染）

**Props 变更**:
- 新增 `selectedReportPath?: { pathId: number; relPath: string }` — 由 FolderPathsPane 选中报告时回调设置
- 新增 `onReportPathSelected?: (pathId: number, relPath: string) => void` — 回调

**文件树集成**:
- VizTabs 中 FolderPathsPane 的 `onSelectReport` 回调（需要在 FolderPathsPane 中新增一个轻量 `onSelectReport?` prop）
